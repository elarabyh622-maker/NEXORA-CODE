## ملفات المشروع

تنزل حزمة React من `react-starter-v1.zip` وحزمة TypeScript من `typescript-starter-v1.zip` عبر بطاقات المشروع في المنصة. توجد الملفات المنشورة تحت `phase2/apps/web/public/projects/`، ويُنشئها البناء من [مصادر بداية JavaScript](project/starter-js/README.md) و[مصادر بداية TypeScript](project/starter-ts/README.md). يحفظ كل مشروع إصدارات الاعتمادات في `package-lock.json` وإشعاراتها في `LICENSES.md`. يستبعد التغليف `node_modules` و`dist` وبيانات التشغيل.

يظل [مرجع JavaScript](project/reference-js/README.md) و[مرجع TypeScript](project/reference-ts/README.md) منفصلين عن التنزيل. يتضمن كل مرجع عشرة اختبارات لقواعد البيانات والمصدر المحاكي ومحوّل API. في نسخة البداية JavaScript يفشل عمدًا اختبار استقلال النسخة القديمة عند حفظ المنتج؛ يكمل المتعلم الاستبدال باستخدام مصفوفة جديدة. في نسخة البداية TypeScript يفشل عمدًا حارس الأعداد الصحيحة؛ يجب أن ينجح فحص الأنواع قبل الإصلاح وبعده.

ثبت Node.js 24.12 أو أحدث، وافتح PowerShell في مجلد المشروع المنزل ثم نفذ:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run dev
```

في مشروع TypeScript شغّل `npm.cmd run typecheck` كذلك، وشغّل `npm.cmd run build` قبل تسليم أي من المشروعين. فشل اختبار المهمة الأول مقصود؛ راجع README المرفق وأصلح المهمة ثم أعد الاختبار. يعمل مصدر المحاكاة دون Python، ويعيد تحديث الصفحة بياناته وجلساته التجريبية إلى البداية.

يمكن ربط الواجهة اختياريًا بنسخة تدريب مستقلة من [خدمة المرحلة التاسعة](../phase9/README.md). يضبط `VITE_DATA_SOURCE=api` محوّل الطلبات إلى `/api`، وتوجّه إعدادات Vite الطلبات إلى `127.0.0.1:8000`. يشرح README كل مشروع أيضًا بناء الواجهة ونسخ محتويات `dist` إلى `catalogue/static` لاستضافتها من أصل الخدمة نفسه. لا تستخدم بيانات التشغيل التجارية في التدريب.

مختبر الأكواد داخل المنصة التجارية مفعّل لـPython وJavaScript بعد قبول تشغيل فعلي يوم 18 نوفمبر. مختبرا المرحلة الجديدة للكونسول؛ تشغيل JSX وتطبيق React متعدد الملفات يتم محليًا في المشروع المنزل. يوضح [دليل المضيف](../phase3/host/README.md) فصل مهلة تهيئة البيئة عن مهلة كود المتعلم، وطبقة التخزين المؤقتة ومزامنة مصادر المشغّل.

## البناء والتحقق

ثبت اعتمادات المرجعين قبل فحص الأمثلة؛ يحتاج الفحص مترجم TypeScript المثبت في `reference-ts`. من جذر المستودع:

```powershell
Push-Location phase10/project/reference-js
npm.cmd ci
npm.cmd test
npm.cmd run build
Pop-Location
Push-Location phase10/project/reference-ts
npm.cmd ci
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
Pop-Location
python -B phase10/build_curriculum.py
python -B phase10/build_curriculum.py --check
```

يتحقق `--check` من تطابق الحزمة مع المصدر وبصمة أساس المرحلة التاسعة وعدم تكرار المعرفات، ثم ينفذ 17 حالة JavaScript للأمثلة والكونسول ومختبريه، ومثالَي ESM متعددَي الملفات. يترجم أمثلة JSX السبعة ويفحص HTML الناتج من العرض الأول على الخادم. ويفحص سبعة أمثلة TypeScript، منها أربعة أخطاء تعليمية متوقعة يطابق رموز تشخيصها. يتحقق أيضًا من تطابق أرشيفَي البداية مع ملفات المصدر.

**PASSED:** اجتاز `--check` الحالات الـ17 ومثالَي ESM وأمثلة JSX السبعة وفحوص TypeScript السبعة وتطابق أرشيفَي ZIP. اجتاز كل مرجع اختباراته العشرة وبناء الإنتاج. بصمة الحزمة هي `a418cbb4f6f64fc809716f4fc634ba6b6df50e75e083bdd6925cfbde4d80df62`.

**نسختا البداية:** نجح تسعة اختبارات وفشل اختبار واحد مقصود في كل نسخة، مطابق لمهمة المتعلم الموضحة أعلاه. نجح بناء الإنتاج للنسختين وفحص أنواع TypeScript؛ لا تُسجّل اختبارات البداية كلها PASSED قبل حل المهمة.

اجتاز [فحص إصدار المنهج](check-release.py) ثماني مجموعات HTTP على PostgreSQL مؤقت حقيقي: النشر وإعادته دون تغيير سجل audit، وثبات حزمة المرحلة التاسعة وخطتها المحفوظة، والخطط الجديدة ذات 33 و40 و43 و72 درسًا، وصلاحيات تنزيل ZIP وإلغاؤها، وصلاحية درس منفرد لكل من `react-07` و`tsreact-03` والتصحيح وإعادة الطلب بالمفتاح نفسه، واستقلال الأسعار وإخفاء الإجابات عن المتعلم. نجحت اختبارات Domain الـ110.

اجتاز النسخ والاستعادة التجاريان مطابقة الجداول الـ16 قبل التفعيل. فشلت المحاولة الأولى لأن PostgreSQL كان متوقفًا؛ شُغّل العنقود نفسه واستعاد WAL تلقائيًا ثم نجحت إعادة الفحص. نجح فحص staging للبيئة Production على المنفذ `5198` للقراءة فقط وأُوقف بعده. تحقق الكتالوج المنشور من الأهداف الـ15، وأظهر المتصفح الأهداف الأربعة الجديدة، وبقي رابط تجربة المتعلمين المتقاعد يعيد `404`.

اجتاز Edge `157.0.4341.60` بدقة `375×812` ثمانين سيناريو متصفح: 13 لكل مرجع ونسخة بداية في وضع المحاكاة، و14 لكل مرجع مع API. شملت الفحوص StrictMode وإلغاء الطلب القديم وحفظ أحدث نتيجة، وخطأ `503` وإعادة البحث نفسه، ودخول القارئ والمدير والإضافة والتعديل والحذف وصفر السعر والكمية واستعادة الصفحة وتفريغ الجلسة المحلية. استُخدمت محاكاة متحكم بها لخطأ `503` والرد المتأخر، ونسختان مؤقتتان من مشروع المرحلة التاسعة وقاعدتا SQLite لاتصال API. أثبت فحص نسخة بداية JavaScript بقاء التعديل معطلًا وفق المهمة التعليمية، ولا يحوّل نجاح هذه السيناريوهات فشل اختبار المهمة المقصود إلى نجاح. طابقت أرشيفات الويب وBackend وReact وTypeScript الأربعة في `wwwroot` المنشور ملفات المصدر وبصمات حزم البداية المفحوصة.

يمكن إعادة فحص المشروعات عبر [check-projects.py](project/check-projects.py)، الذي يستدعي [check-browser.cjs](project/check-browser.cjs). يحتاج اعتمادات المرجعين وبيئة Python للمرحلة التاسعة. اضبط `PLAYWRIGHT_CORE` على مسار وحدة `playwright-core` المثبتة و`BROWSER_EXECUTABLE` على ملف Edge التنفيذي عند الحاجة، ثم شغّل من الجذر:

```powershell
& 'phase9/project/.local/venv/Scripts/python.exe' -B phase10/project/check-projects.py
```

فحص العرض الأول وحده لا يثبت سلوك React التفاعلي؛ يغطيه فحص المتصفح المحدد أعلاه. يقتصر تحقق المشروعات على Edge بالإصدار والعرض المذكورين، ولا يغطي أجهزة حقيقية أو قبول متعلم بشري أو قبولًا نهائيًا. لا تثبت هذه النتائج تشغيل Python داخل المنصة التجارية.
