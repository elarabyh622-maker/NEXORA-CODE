فُعّل الإصدار `phase12-ar-v1` تجاريًا يوم 19 نوفمبر 2026. يظهر الهدف الجديد ضمن صفحة أسعار المسارات، ويضبط مسؤول المنصة السعر من إعدادات المستخدمين. [الرابط التجاري](https://desktop-phkhegp.tail3372f6.ts.net:10000/)

## مشروع لوحة مبيعات متجر افتراضي

تضم حزمة البداية `applied-data-starter-v1.zip` ملفي CSV في `data/`، و`clean.py` لتنظيف السجلات وربط المنتجات، و`queries.sql` لإنشاء ملخصين في SQLite، و`metrics.py` للإحصاء والرسم، و`sales_report.py` لربط المراحل وتصدير الملفات. تضم الحزمة أيضًا تعليمات التشغيل والاختبارات وقائمة الاعتمادات والتراخيص. يمكنك مراجعة [دليل الحل المرجعي](project/reference/README.md).

افتح PowerShell في المجلد الذي يحتوي على `sales_report.py` بعد فك الضغط. بيئة التشغيل المحلية التي تستهدفها الحزمة هي Python 3.14 ‏64-bit على Windows.

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r requirements.txt
.\.venv\Scripts\python.exe -B -m unittest -v
```

من المتوقع أن يفشل اختبار واحد في نسخة البداية عند مقارنة إيرادات الأشهر. أكمل موضع `TODO` في `queries.sql` باستخدام `LAG(revenue_piastres)` بترتيب `month`، ثم أعد الاختبارات قبل تشغيل التقرير.

```powershell
.\.venv\Scripts\python.exe -B -m unittest -v
.\.venv\Scripts\python.exe -B sales_report.py --out-dir output
```

افتح `output/index.html` محليًا واقرأه بجوار `monthly.csv` و`summary.json`. يُصدّر المشروع أيضًا `cleaned_sales.csv` و`monthly.png`. اختر اسم مجلد إخراج جديد لكل تشغيل. احسب الإيراد بالقروش، وطابق عدد سطور البيع وإيرادها مع الملخص، ثم اشرح فرق الأشهر في ثلاثة أسطر. يستخدم التقرير الشهر السابق الموجود في البيانات. في هذه العينة يقارن أبريل بفبراير لغياب مارس. تظهر قيمة المقارنة فارغة لأول شهر.

## الاعتمادات والتنفيذ

تُثبّت إصدارات الاعتمادات الاثني عشر المحددة في [requirements.txt](project/reference/requirements.txt) داخل البيئة الافتراضية المحلية. يسجّل ملف [LICENSES.md](project/reference/LICENSES.md) تراخيص الاعتمادات. تستخدم أمثلة pandas والمشروع الاعتمادات محليًا، ويستخدم مختبر Python التجاري المكتبة القياسية فقط. أمثلة SQL قابلة للتشغيل في SQLite محليًا.

## بناء الحزمة والتحقق المحلي

نفّذ الأوامر من جذر المستودع. أنشئ البيئة المحلية وثبّت الاعتمادات مرة واحدة قبل تشغيل فحوص أمثلة pandas.

```powershell
python -m venv phase12/.local/venv
$phase12Python = '.\phase12\.local\venv\Scripts\python.exe'
& $phase12Python -m pip install --only-binary=:all: -r phase12/project/reference/requirements.txt
& $phase12Python -B phase12/build_curriculum.py
& $phase12Python -B phase12/build_curriculum.py --check
```

تكتب عملية البناء [حزمة المنهج](dist/curriculum.json) وتضع ملف ZIP الخاص بنسخة البداية في مجلد مشاريع الواجهة. تُولَّد نسخة البداية من عشرة ملفات مراجعة، ويستبدل البناء قيمة الإيراد السابق في `queries.sql` بموضع `TODO`. طابقت مخرجات 17 مثالًا النتائج المتوقعة محليًا، بواقع خمسة أمثلة لـpandas وخمسة للإحصاء وستة لـSQL وواحد للمشروع. نجحت حالات حل المختبر الأربع واختبارات الحل المرجعي الخمسة. فشل اختبار SQL المقصود وحده عند فك ZIP، ثم نجحت الاختبارات الخمسة بعد إكماله. يحتاج تفسير التقرير إلى قراءة بشرية.

بصمة SHA-256 للحزمة هي `71e7df9dffaf548b3ad6a98f60d8acc3002d4b24addb2679db0e5ed93e8d77d2`.

## التحقق من النشر

اجتاز [الفحص المعزول](check-release.py) خمس مجموعات HTTP على PostgreSQL حقيقي. غطى ترقية الإصدار وإعادة تفعيله، وبقاء خطة المرحلة 11، وأعداد المحتوى، واستقلال السعر، وتخطيط الهدف، وإخفاء الإجابات، وصلاحيات ZIP على مستوى الهدف والدرس مع التحقق من إلغائها. فُحصت استعادة قاعدة النسخة التجارية قبل التفعيل وتطابقت بصمات 16 جدولًا. ظهر الإصدار في الكتالوج العام، وعرض المتصفح المسار ودروسه الستة عشر وبطاقة المشروع. تحقق الرابط التجاري من حجب التنزيل للزائر.

اجتازت الحالات الأربع للمختبر الجديد تنفيذًا مباشرًا عبر gVisor. يغطي هذا الفحص المشغّل، وتغطي اختبارات PostgreSQL نطاق إتاحة التمرين. لم تُجرَ في هذه المرحلة تجربة تشغيل من حساب متعلم مدفوع على الإنتاج أو جلسة قبول بشري للتقرير.
