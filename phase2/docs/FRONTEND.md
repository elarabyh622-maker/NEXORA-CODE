## السلوك المنفذ

- `lang=ar` و`dir=rtl`، هوية أخضر داكن وسطوح فاتحة مشتقة قراءةً من المرحلة الأولى، دون نسخ بياناتها كبديل للخادم. خط نظام محلي دون طلبات خطوط أو صور خارجية. تخطي إلى المحتوى، تنقل hash، روابط مباشرة للدروس والخطط، عناوين مرتبة، labels ظاهرة، focus واضح، radio/checkbox/select أصلية، أهداف نقر 44px، وإلغاء الحركة عند reduced-motion.
- استكشاف catalog والمحتوى والقاموس والدروس دون حساب. اختيارات الهدف تظهر sample مقابل planned بوضوح؛ المحتوى الحالي ثلاثة دروس عينة، وليس منهجًا كاملًا. خيارات لغة أمثلة Python/JavaScript مستقلة تمامًا عن اختيار هدف الخطة، وتُرشح sections ذات language وأمثلة المؤلف الموجودة فقط.
- إنشاء حساب متعلم ودخول وخروج فعلي، مع طول كلمة مرور التسجيل 12–128 واسم ظاهر واسم مستخدم يدعم العربية وفق عقد الخادم. autoComplete وإظهار كلمة المرور واللصق متاحة. يحتفظ الخادم بالجلسة عبر cookie، ويستخدم العميل رمز CSRF في ذاكرة الطلب.
- «تحديث حماية الجلسة» يتحقق من `/auth/me` ويطابق معرفه مع `userId` من `/auth/csrf`. يحصل كل طلب كتابة على رمز جديد للهوية المعروضة، ويرسل `X-CSRF-TOKEN` وcookies من نفس الأصل. إذا اختلف الحساب أو غاب `userId` يتوقف الطلب قبل إرسال جسمه. يعيد العميل التحقق بعد تسجيل الدخول أو إنشاء الحساب أو الخروج، وعند رفض CSRF أو انتهاء الجلسة.
- تتلقى التبويبات إشعارًا عبر `BroadcastChannel` بعد تغيير الجلسة. يحمل الإشعار حدث التغيير فقط. يعاد التحقق أيضًا عند التركيز والعودة للتبويب. يؤدي تبدل الحساب إلى إلغاء طلباته المعلقة واستبدال خريطة مسوداته وإعادة تهيئة صفحات الحساب. يبقى نص المسودة في الذاكرة عند إعادة التحقق من الحساب نفسه. يتأكد العميل من `/auth/me` بعد استجابة القراءة الخاصة وقبل عرضها، ويفسر 403 و404 بحسب الهوية المتحققة. تحدد جلسة الخادم الهوية التي يُنفذ الطلب تحتها.
- معاينة الخطة من POST الخادم فقط؛ لا مخطط بديل في الواجهة، ولا إرسال achievedSkillIds. حفظ الخطة يرسل expectedCurrentRevision عند وجود خطة؛ 409 يجلب أحدث خطة ويطلب مراجعتها قبل حفظ مراجعة جديدة. التاريخ GET واستعراض snapshot عبر learning-plans/{id} فعليان. تغيير الإصدار لا ينقل خطة قديمة تلقائيًا. تاريخ الخطط وخطوات snapshot يظلان قابلين للعرض حتى عند تعذر قراءة محتوى إصدار متقاعد؛ تظهر معرّفات الدروس بدل اختلاق عناوين غير متاحة.
- الدروس تأتي من endpoint الدرس، والأمثلة شرح وتتبّع فقط؛ لا runner ولا eval ولا AI. لا تعريف أو قراءة acceptedAnswers ولا تصحيح في المتصفح؛ explanation بعد التصحيح يأتي من نتيجة الخادم.
- إرسال المحاولة إلى practice/attempts مع idempotencyKey. يتكرر نفس المفتاح عند إعادة نفس answer/hints بعد فشل شبكة غير مؤكد، وعند العودة للدرس أثناء بقاء الصفحة مفتوحة. تغيير payload يولد مفتاحًا جديدًا؛ لا retry آلي للطلبات غير الآمنة. نتيجة alreadyRecorded مفهومة بالعربية. التقدم كله GET من الخادم، solved وتفاصيل الدروس والمهارات وعدد المحاولات دون زيادة محلية تفاؤلية. العرض يقول ممارسة، ولا يدّعي demonstrated أو شهادة إتقان.
- المسودة GET ثم PUT expectedVersion؛ الصفر للإنشاء. لا يُسمح بالحفظ قبل حسم قراءة المسودة. تحرير النص قبل انتهاء GET لا يضيع النص. تعارض 409 يُبقي نص المتعلم ويجلب النسخة الأخرى بجواره؛ زر صريح «حفظ نسختي بدل المحفوظة» يستخدم نسختها الأحدث، وأي تعارض لاحق يظهر مجددًا. النص يبقى في الذاكرة عند التنقل بين الدروس أو تغيير لغة المثال؛ قبل إغلاق الصفحة يظهر تحذير المتصفح إن بقيت مسودات غير محفوظة. تأكيد save لا يبدل نصًا أحدث كتبه المستخدم أثناء الطلب. طول النص 4096 موافق لحد Backend الحالي.
- تعرض واجهة فريق المحتوى الإصدارات وحالتها ونسختها والإصدار المحدد للبداية. يمكن للمؤلف والمدير إنشاء حزمة JSON، وتتاح الانتقالات حسب الدور مع `expectedVersion`. يختار Reviewer أو Admin إصدار بداية منشورًا عبر `POST /admin/releases/{id}/activate` مع `{expectedVersion}`. تعاد قراءة القائمة عند تعارض النسخة، ويتحدث الفهرس بعد نجاح التفعيل.
- عند وجود إصدارات منشورة بلا `activeReleaseId` تعرض نقطة البداية والخطة اختيارًا صريحًا. عند تعذر قراءة إصدار محدد تظهر الإصدارات المنشورة البديلة ويظل تاريخ الخطة متاحًا. يتغير إصدار البداية للزيارة الجديدة عند تفعيله، وتبقى مراجعات الخطط مرتبطة بإصداراتها الأصلية.
- أخطاء 401/403/409/429/500/503 ورسائل الشبكة بالعربية، مهلة 20 ثانية، أزرار retry للقراءات. HTML مكان JSON يفشل صراحة. لا mock success ولا عينة محلية عند غياب API، ولا تخمين تقدم/حفظ ناجح.

## ملاحظات وقبول الدمج

1. طابقت الواجهة `userId` من `Auth.cs` و`activeReleaseId` ومسار `activate` من `Content.cs` في عقد 2026-11-11. `activeReleaseId` هو معرف الإصدار النصي، بينما يستخدم مسار التفعيل UUID.
2. يتحقق المنسق من P2-01 في تبويبين بحسابين، ومن بقاء حفظ المسودة مرتبطًا بالحساب الصحيح بعد تبدل الجلسة. يتحقق من P2-03 بتقاعد إصدار البداية مع وجود بديل منشور، ثم اختيار البديل وتفعيله وعرض خطة تاريخية مثبتة على الإصدار السابق.
3. فحص الهاتف المرئي اقتصر على الحساب وحالة تعطل الخدمة؛ home/plan/lesson/progress/admin على بيانات الخادم، keyboard شامل، landscape، وقراءة قارئ شاشة فعلية لم تُقبل بصريًا في هذه الجلسة. CSS مصمم لتلك الأحجام لكن هذا ليس دليل اختبار لها.
4. المسودات غير المحفوظة ومفاتيح المحاولات تبقى في ذاكرة الصفحة فقط، ولا تبقى بعد الإغلاق/إعادة التحميل. المسودات التي أكد الخادم حفظها تبقى في الحساب. الخروج المقصود أو الدخول بحساب آخر يمسح ذاكرة الهوية السابقة.
5. إذا تقاعد إصدار، فالـAPI لا يسمح بقراءة دروسه أو محاولات جديدة حسب قراره الموثق. الواجهة لا تلتف على ذلك. المعاينة التاريخية تعرض snapshot، ويمكن محاولة فتح إصدار الخطة أو اختيار إصدار منشور آخر صراحة.
6. لا نسخ إلى wwwroot ولا نشر أو Git أو تغيير دور حساب بواسطة هذه الجلسة.
