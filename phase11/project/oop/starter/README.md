# مشروع مخزون صغير بـPython

يتتبّع المشروع كمية كل منتج وقيمة المخزون. جميع البيانات تجريبية ويعمل المشروع محليًا بالمكتبة القياسية لـPython 3.10 أو أحدث.

## التشغيل على Windows

فك ضغط التنزيل وافتح PowerShell في المجلد الذي يحتوي `main.py`. تحقّق من نسخة Python، ثم أنشئ بيئة واستخدم المفسّر داخلها مباشرة.

```powershell
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe main.py
```

إذا كان `py` غير متاح، استخدم `python --version` و`python -m venv .venv` مع Python 3.10 أو أحدث. تشغيل المفسّر مباشرة يكفي في PowerShell.

## العقد

- `Product` قيمة ثابتة تحمل رمز `sku` وسعر `unit_price`. الرمز نص غير فارغ بلا مسافات في طرفيه وحروفه حساسة لحالة الأحرف. السعر عدد صحيح غير سالب بوحدات صغرى افتراضية. مثلًا سعر `125` يعني 125 وحدة صغرى.
- `StockLine` يدير كمية منتج واحد تبدأ عند صفر. الاستلام والسحب يقبلان أعدادًا صحيحة موجبة فقط ويستبعدان `bool`. يسمح السحب المساوي للرصيد بالوصول إلى صفر. السحب الزائد أو الكمية غير الصالحة يرفعان `ValueError` مع بقاء الرصيد كما كان.
- `Inventory` يحتوي سطرًا لكل رمز ويسند إليه تحديث الكمية. التسجيل المكرر يرفع `ValueError`، والوصول إلى رمز غير مسجل يرفع `KeyError`. قيمة المخزون هي مجموع حاصل ضرب كمية كل سطر في سعر وحدته. سطر السعر صفر قد يحتوي وحدات.

## مهمتك

1. شغّل الاختبارات. يعرض `test_withdraw_full_stock` فشلًا مقصودًا في البداية لأن السحب الصحيح يترك الرصيد عند 3. تمر الاختبارات السبعة الأخرى.
2. أكمل مهمة `TODO` الوحيدة في `StockLine.withdraw` داخل `inventory.py`. نفّذ تعديل الرصيد بعد فحص الكمية والحد الأعلى.
3. أعد تشغيل الاختبارات. تتوقع ثمانية اختبارات ناجحة. يختبر أحدها السحب الزائد ويتحقق من بقاء القيمة والرصيد، ويختبر آخر استقلال كميتي مخزنين سجّلا المنتج نفسه.
4. شغّل `main.py` بعد الإصلاح وقارن المخرجات التالية.

```text
PEN: 0
NOTE: 2
total_minor_units: 720
```

`__post_init__` يستدعيه المُنشئ الذي تولّده `dataclass` في `Product` لفحص القيم بعد تهيئة الحقول. بادئة `_` تميّز تفاصيل التنفيذ مثل `_quantity`. تقرأ `@property` الكمية الحالية دون أقواس، وتوضع قاعدة تغييرها في `receive` و`withdraw`. في الاختبارات، ينشئ `setUp` مخزونًا جديدًا لكل اختبار، ويميّز `subTest` كل حالة داخل الحلقة في تقرير `unittest`.
