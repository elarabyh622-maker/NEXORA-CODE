يبدأ مسار OOP بعد `pyproj.types`: الأساس، ثم Python، ثم Python للمشروعات، ثم دروسه الستة. يركز على حالة الكائن وقواعد تغييرها والتركيب والتفويض، وينتهي بمخزون محلي صغير. يبدأ حل المشكلات بعد `alg.recursion`؛ يضيف إلى خطة الخوارزميات ستة دروس في عقود المسائل والأمثلة المضادة وخريطة العدّ والمؤشرين والنافذة وفصل الدوال. **OOP ليس متطلبًا للخوارزميات أو حل المشكلات.** تتقلص الخطط عندما يمتلك المتعلم مهارات سابقة مثبتة؛ أعداد الجدول تخص متعلمًا جديدًا.

## المشروعات والتنزيلات

توجد لكل مشروع ملفات بداية مستقلة وحل مرجعي مكتمل، وجميع البيانات خيالية. تستخدم المشروعات Python 3.10 أو أحدث أو Node.js 22 أو أحدث والمكتبات القياسية فقط؛ لا تحتاج إلى تثبيت حزم عبر npm أو pip. اختر لغة واحدة أولًا في المشروعات التي تقدم اللغتين.

| المشروع | مصدر البداية | الحل المرجعي | ملف التنزيل |
| --- | --- | --- | --- |
| تقرير البحث والعدّ | [algorithms/starter](project/algorithms/starter/README.md) | [algorithms/reference](project/algorithms/reference/README.md) | `algorithms-starter-v1.zip` |
| مخزون صغير بالكائنات | [oop/starter](project/oop/starter/README.md) | [oop/reference](project/oop/reference/README.md) | `oop-starter-v1.zip` |
| مكتبة تحديات النصوص والقوائم | [problem-solving/starter](project/problem-solving/starter/README.md) | [problem-solving/reference](project/problem-solving/reference/README.md) | `problem-solving-starter-v1.zip` |

ينشئ البناء ملفات ZIP تحت `phase2/apps/web/public/projects/` من مصادر `starter`، ويحتفظ بـ`reference` للمراجعة منفصلًا عن التنزيل. تتضمن الحزم تعليمات التشغيل والاختبارات وإشعارات `LICENSES.md`. تخضع التنزيلات لصلاحية الهدف أو درس المشروع المنفرد. يتيح هدف حل المشكلات أيضًا مشروع الخوارزميات الذي يدخل ضمن متطلباته، ولا يمنح تنزيلات أهداف أخرى غير مرتبطة.

تحتوي كل نسخة بداية على موضع TODO مقصود لكل لغة، ولذلك يجب قراءة نتيجة اختبار البداية كما هي:

- الخوارزميات: تنجح أربعة اختبارات ويفشل واحد في كل لغة قبل إكمال البحث الثنائي عن أول موضع في النسخة المرتبة.
- OOP: تنجح سبعة اختبارات ويفشل اختبار السحب المساوي للرصيد حتى يكتمل تحديث الكمية في `StockLine.withdraw`.
- حل المشكلات: يفشل اختبار العقد الواحد في كل لغة عند `complete solve`. بعد إكمال الدالة يمر الاختبار على جميع بيانات الاختبار؛ توقفه عند أول حالة في البداية لا يعني أن بقية الحالات نُفذت.

نجاح فشل البداية المتوقع لا يحوّل الحل غير المكتمل إلى مشروع ناجح. أكمل TODO، ثم أعد الاختبارات واشرح عقد الحل وحدوده؛ الشرح يحتاج مراجعة بشرية مستقلة عن تصحيح النتائج.

## تشغيل المشروعات على Windows

الأوامر التالية من جذر المستودع لتشغيل المراجع. عند العمل على نسخة البداية استبدل `reference` بـ`starter`، أو نفّذ أوامر اللغة من مجلد الحزمة بعد فك الضغط. إذا لم يكن `python` معروفًا وكان Python Launcher مثبتًا، استخدم `py -3` بدلًا منه.

```powershell
Push-Location phase11/project/algorithms/reference
'{"values":[12,2,12,25],"target":12}' | python -B search.py
python -B -m unittest -v test_search.py
'{"values":[12,2,12,25],"target":12}' | node search.cjs
node --test test_search.cjs
Pop-Location

Push-Location phase11/project/oop/reference
python -B main.py
python -B -m unittest -v
Pop-Location

Push-Location phase11/project/problem-solving/reference/python
'{"task":"count","text":"red blue red"}' | python -B main.py
python -B -m unittest -v
Pop-Location

Push-Location phase11/project/problem-solving/reference/javascript
'{"task":"window","items":[-5,-2,-4],"k":2}' | node main.cjs
node test.cjs
Pop-Location
```

يوضح README كل مشروع عقد الإدخال والمخرج، والفهارس، والفراغ، والتكرار، والصفر، والسالب، والتحقق من الأنواع. تقرأ أداتا الخوارزميات وحل المشكلات مستند JSON كاملًا من stdin، ويمكن تنسيقه على عدة أسطر. تقبل هاتان الأداتان الأعداد ذات القيمة الصحيحة مثل `2.0` وتستبعدان القيم المنطقية والكسور غير الصحيحة. يطبق مشروع OOP عقد أنواع Python الموضح في دليله. لا تتطلب هذه المشروعات تشغيل خادم أو قاعدة بيانات.
