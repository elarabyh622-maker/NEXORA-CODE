# مشروع مخزون متجر صغير بـ C# و.NET

برنامج سطر أوامر يضيف الأصناف ويستقبل الكميات ويصرفها ويعرض الرصيد الحالي. يحفظ البرنامج التغييرات في ملف JSON ويقرأ الملف في كل تشغيل. بيانات الدفاتر والأقلام في المشروع خيالية.

## شغّل نسخة البداية على Windows

1. نزّل وثبّت **.NET 10 SDK** المناسب لجهازك من [صفحة تنزيل .NET 10 لدى Microsoft](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). افتح PowerShell واكتب `dotnet --list-sdks` للتأكد من ظهور إصدار يبدأ بـ `10.0`.
2. فك ملف ZIP في مجلد جديد واستخدم **Open in Terminal** داخل المجلد الذي يحتوي هذا الدليل ومجلد `Inventory.Cli`.
3. نفّذ الأمرين التاليين مرة واحدة لنسخ العينة إلى ملف العمل، ثم اعرض الأرصدة.

```powershell
New-Item -ItemType Directory -Force .local
Copy-Item data/sample-inventory.json .local/inventory.json
dotnet run --project Inventory.Cli -- list
```

هتشوف الصنف `P-101` برصيد 12 و`P-102` برصيد 4. الأوامر التالية تعدّل `.local/inventory.json` داخل مجلد التشغيل. تقدر تختار ملفًا ثانيًا باستخدام `--file` قبل اسم الأمر. لو الملف غير موجود، يبدأ المخزون فارغًا ويحفظه البرنامج عند أول تعديل ناجح.

```powershell
dotnet run --project Inventory.Cli -- add P-103 "كابل شحن"
dotnet run --project Inventory.Cli -- receive P-101 3
dotnet run --project Inventory.Cli -- list
```

الإضافة تبدأ الصنف الجديد برصيد صفر. يرفع أمر `receive` رصيد `P-101` إلى 15. اكتب الكمية بالأرقام من 0 إلى 9، واستخدم علامات الاقتباس مع الاسم اللي يحتوي على مسافات.

## أكمل صرف الكمية

```powershell
dotnet run --project Inventory.Tests
```

في نسخة البداية ينجح أربعة من خمسة اختبارات. اختبار `RemoveStockValidatesBeforeChanging` يبدأ بفشل مقصود. افتح `Inventory.Core/Inventory.cs` وأكمل موضع `TODO` في الدالة `RemoveStock`. راجع طريقة استقبال الكمية في `ReceiveStock` وطبّق القواعد الآتية.

- ارفض كمية صفر أو أقل. استخدم `ValidateMovementQuantity` للتحقق بنفس قواعد الاستقبال.
- ابحث عن الصنف عبر `GetProduct`. الصرف يحتاج كودًا مسجلًا.
- لو الكمية المطلوبة أكبر من الرصيد، ارفع `InvalidOperationException` برسالة واضحة قبل تعديل الصنف.
- اقبل صرف كمية تساوي الرصيد، وحدّث الكمية وأرجع الرصيد المتبقي. راجع تركيب `with` المستخدم لتحديث كمية الصنف عند الاستقبال.

شغّل الاختبارات مرة ثانية. المفروض تنجح الاختبارات الخمسة. بعد استقبال 3 وحدات من `P-101` في الأوامر السابقة، جرّب صرف 5 ثم اطلب صرف 11 وقارن الرصيد بعد كل طلب.

```powershell
dotnet run --project Inventory.Cli -- issue P-101 5
dotnet run --project Inventory.Cli -- list
dotnet run --project Inventory.Cli -- issue P-101 11
$LASTEXITCODE
dotnet run --project Inventory.Cli -- list
```

بعد نجاح صرف الخمسة يظهر الرصيد 10 في تشغيل جديد. صرف 11 يرجع رمز الخروج `1` ويظل الرصيد 10 في العرض التالي. احتفظ بنتيجة الاختبارات واكتب شرحًا قصيرًا للمكان اللي بتتحقق فيه من الرصيد والمكان اللي بتقرأ وتحفظ فيه JSON.

## ملفات المشروع

- `Inventory.Core/Inventory.cs` يحتفظ بالأصناف في قاموس بالمفتاح `Sku`. تُهمل المسافات المحيطة بالكود وتُوحّد حالة الحروف. يحتفظ `Product` بالكود والاسم والرصيد.
- `Inventory.Core/InventoryFile.cs` يحول بين الكائنات وJSON. يكتب نسخة كاملة مؤقتة قبل استبدال ملف العمل. تُرفض البيانات التالفة أو الأرصدة السالبة.
- `Inventory.Cli/Program.cs` يقرأ أوامر PowerShell ويحدد متى يقرأ الملف ويحفظه. يشغّل التعديلات بالتتابع لملف واحد باستخدام قفل بجواره بامتداد `.lock`. لو حاول أمران تعديل نفس الملف في اللحظة نفسها، يرفض البرنامج الأمر الذي لم يحصل على القفل. أعد تنفيذ الأمر المرفوض بعد انتهاء الأمر الأول.
- `Inventory.Tests/Program.cs` يشغّل اختبارات التحقق والتخزين في ملف مؤقت مستقل عن بيانات التدريب. يعرض `PASS` أو `FAIL` لكل اختبار ثم يرجع رمز خروج يلائم النتيجة.

المشروع مثال محلي للتعلم بملف واحد ومستخدم واحد. تقدر تجرب ملفًا منفصلًا بالتشغيل التالي.

```powershell
dotnet run --project Inventory.Cli -- --file .local/second.json list
```
